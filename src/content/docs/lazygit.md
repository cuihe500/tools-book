Lazygit 是 Git 的终端图形界面（TUI）：在一个界面里看工作区、差异、分支、提交和贮藏，并把常见 Git 操作做成按键和菜单。它不会替 Git 改变工作方式；按键最终仍是在执行 Git 命令，所以重置、丢弃、变基等操作一样有风险。

下面是 **当前默认键位**。键位可以在配置文件的 `keybinding:` 下覆盖，且同一个键会随面板变化；先看焦点在哪个面板。大小写有别：`p` 和 `P`、`r` 和 `R` 是不同操作。忘记时按 `?` 看当前界面的完整帮助，优先相信它。

## 通用操作与导航

| 键 | 作用 |
|---|---|
| `?` | 打开当前上下文可用操作的菜单／帮助 |
| `Tab` | 在可切换的面板或视图之间切换 |
| `Enter` | 进入、查看或确认；具体含义由当前选项决定 |
| `Esc` | 取消、关闭菜单或返回上一层 |
| `p` / `P` | 从当前分支的上游拉取 / 推送当前分支到上游；没有上游时会先询问如何配置 |
| `R` | 刷新 Git 状态；**不会**执行 `git fetch` |
| `f` | 在「文件」面板抓取远程更新（fetch） |
| `z` / `Z` | 撤销 / 重做 reflog 中的提交相关操作；不处理工作区改动和贮藏 |
| `m` | 打开进行中的合并／变基选项，如继续、中止、跳过 |
| `@` | 打开命令日志菜单，查看 Lazygit 实际执行过的命令 |
| `:` | 执行 Shell 命令 |
| `/` | 搜索或过滤当前列表／视图 |
| `[` / `]` | 切换上一个 / 下一个标签页 |
| `+` / `_` | 切换到下一个 / 上一个屏幕模式（正常、半屏、全屏） |
| `q` / `Ctrl+C` | 退出 |

列表较长时，`,` / `.` 翻上一页／下一页，`<`（或 `Home`）到顶部，`>`（或 `End`）到底部。官方当前默认键位表**没有**把 `1`–`5` 或 `h` / `l` 列作侧栏面板跳转；不要把它们当成固定默认键位。

## 文件：暂存、提交与丢弃

在「文件」面板中，`Space` 操作的是选中的文件；提交只会提交已暂存的内容。

| 键 | 作用 |
|---|---|
| `Space` | 暂存 / 取消暂存选中文件 |
| `a` | 切换工作区所有文件的暂存状态 |
| `Enter` | 选中文件时进入逐块／逐行暂存；选中目录时折叠／展开目录 |
| `c` | 提交已暂存的文件 |
| `w` | 提交变更但跳过 pre-commit 钩子 |
| `C` | 调用 Git 配置的编辑器撰写提交信息 |
| `A` | 用已暂存改动修补（amend）最后一次提交 |
| `s` / `S` | 贮藏所有改动 / 打开贮藏选项（可选择只贮藏已暂存或未暂存内容） |
| `f` | 从远程抓取更新（fetch） |
| `r` | 刷新文件列表 |
| `i` | 将选中文件加入 `.gitignore` |
| `` ` `` | 在平铺文件列表与树形文件列表之间切换 |
| `d` | 打开选中文件的「放弃改动」选项 |
| `D` | 打开工作树重置选项，例如清空工作树 |
| `M` | 打开合并冲突处理选项 |
| `Ctrl+B` | 按 Git 状态过滤文件 |

`d`、`D`、`A` 都可能丢弃内容或改写提交；先在确认框里核对影响范围。`f` 是 fetch，不会自动合并或变基。

### 逐块／逐行暂存

在文件上按 `Enter` 进入。这里最有价值的是把一个文件中不同目的的改动拆开提交。

| 键 | 作用 |
|---|---|
| `Space` | 切换选中行的暂存状态 |
| `v` | 切换范围选择，再移动光标选择多行 |
| `a` | 在逐行选择和按代码块（hunk）选择之间切换 |
| `Tab` | 在未暂存和已暂存的改动视图之间切换 |
| `d` | 对未暂存改动是丢弃；对已暂存改动是取消暂存 |
| `E` | 在外部编辑器中编辑选中的代码块 |
| `c` / `w` / `C` | 提交 / 跳过钩子提交 / 用 Git 编辑器提交 |
| `Esc` | 返回文件面板 |

高级的「构建补丁」视图中，`Space` 和 `d` 的含义不同；不要把上表直接套过去，按 `?` 查看该视图的提示。

## 本地分支：检出、合并与变基

「分支」面板通常同时有本地和远程分支。下表以本地分支为主；在远程分支上按 `Space` 会基于该远程分支检出本地分支，或进入分离 HEAD。

| 键 | 作用 |
|---|---|
| `Space` | 检出选中分支 |
| `n` | 新建分支 |
| `c` | 按名称检出分支；在输入框中输入 `-` 可切回上一个分支 |
| `-` | 直接检出上一个分支 |
| `w` | 新建 worktree |
| `M` | 将选中分支合并到当前检出的分支，可选择普通合并或 squash merge |
| `r` | 将当前检出的分支变基到选中分支上 |
| `f` | 将当前分支快进到其上游分支 |
| `u` | 打开上游选项：设置、取消或重置到上游 |
| `R` | 重命名分支 |
| `T` | 从选中分支创建标签 |
| `o` / `O` | 创建拉取请求 / 打开创建拉取请求选项 |
| `d` | 打开删除本地／远程分支的选项 |
| `g` | 打开重置选项 |
| `F` | 强制检出，丢弃工作目录里的所有本地改动 |

`r`、`g`、`d` 和 `F` 风险较高。尤其变基会改写当前分支历史；已经推送并被别人基于其开发的分支，不要在不了解后果时变基或强推。

## 提交：整理历史与 cherry-pick

在「提交」面板选中一条提交后操作。改写旧提交、调整顺序、squash、fixup、drop 都会通过交互式变基改写历史，适合尚未共享的本地提交。

| 键 | 作用 |
|---|---|
| `r` / `R` | 改写提交信息 / 用编辑器改写提交信息 |
| `s` | 将选中提交 squash 到下面的提交，提交信息会附加到目标提交信息 |
| `f` | 将选中提交 fixup 到下面的提交，并丢弃选中提交的信息 |
| `d` | 通过变基删除选中提交；后续提交依赖它时可能要解决冲突 |
| `e` | 从选中提交开始交互式变基 |
| `i` | 开始交互式变基；默认处理从 HEAD 到最近合并／主分支提交之间的提交 |
| `Ctrl+J` / `Ctrl+K` | 在变基计划中将选中提交下移 / 上移 |
| `A` | 将当前已暂存的改动 amend 到选中提交 |
| `F` | 为选中提交创建 `fixup!` 提交 |
| `S` | autosquash：压缩选中提交之上或当前分支上的 `fixup!` 提交 |
| `C` / `V` | 标记复制提交 / 粘贴到当前检出分支执行 cherry-pick；按 `Esc` 取消复制选择 |
| `t` | 创建一个反向应用改动的 revert 提交；不改写原有历史 |
| `g` | 打开 reset 选项（soft / mixed / hard） |
| `T` | 为选中提交创建标签 |
| `n` | 从选中提交创建新分支 |

`A` 对旧提交的 amend 也会改写其后的历史。共享提交需要撤销时，通常优先用 `t` 创建 revert，而不是 `d`、`g` 或 amend。

## 贮藏

| 键 | 作用 |
|---|---|
| `Space` | 应用选中贮藏，保留该贮藏项 |
| `g` | 应用并删除选中贮藏（pop） |
| `d` | 删除选中贮藏 |
| `n` | 从选中贮藏创建新分支，再把贮藏应用到该分支 |
| `r` | 重命名贮藏 |

## 合并冲突

从冲突处理界面进入具体文件后：

| 键 | 作用 |
|---|---|
| `h` / `l`（或 `←` / `→`） | 上一个 / 下一个冲突 |
| `j` / `k`（或 `↓` / `↑`） | 选择底部 / 顶部代码块 |
| `Space` | 选定当前冲突代码块 |
| `b` | 同时选取两个代码块 |
| `z` | 撤销上一次冲突解决操作 |
| `e` | 用外部编辑器打开冲突文件 |

解决完成后仍要确认文件内容、暂存已解决文件，并按 `m` 选择继续或中止合并／变基。

## 配置与备查

默认全局配置文件位置：

| 系统 | 路径 |
|---|---|
| Linux | `~/.config/lazygit/config.yml` |
| macOS | `~/Library/Application Support/lazygit/config.yml` |
| Windows | `%LOCALAPPDATA%\lazygit\config.yml`；也会查找 `%APPDATA%\lazygit\config.yml` |

自定义快捷键写在配置中的 `keybinding:` 下。仓库专属的 `<仓库>/.git/lazygit.yml` 会覆盖全局配置；父目录中的 `.lazygit.yml` 也会被加载，适合只给某个项目设定规则。
